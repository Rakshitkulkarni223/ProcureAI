# Deploying ProcureAI to Render

This repo ships a `render.yaml` Blueprint at the repo root that defines two
services:

- `procureai-backend` — FastAPI (Python), built from `backend/`
- `procureai-frontend` — static React build, built from `frontend/`

Render has no managed MongoDB, so the database is an external MongoDB Atlas
cluster referenced via `MONGO_URL`.

## 1. Push this repo to GitHub

Render's Blueprint deploy reads `render.yaml` from a connected GitHub repo, so
make sure these changes are committed and pushed to `origin/main` first.

## 2. Create the Blueprint on Render

1. Go to [dashboard.render.com](https://dashboard.render.com) → **New** → **Blueprint**.
2. Select the `ProcureAI` GitHub repo (authorize Render's GitHub App if this is
   the first time).
3. Render detects `render.yaml` and shows both services
   (`procureai-backend`, `procureai-frontend`).
4. Before clicking **Apply**, you'll be prompted for every env var marked
   `sync: false` in `render.yaml`. Fill in:

   | Service | Key | Value |
   |---|---|---|
   | procureai-backend | `MONGO_URL` | Your MongoDB Atlas connection string |
   | procureai-backend | `GEMINI_API_KEY` | Your Gemini API key |
   | procureai-backend | `GROQ_API_KEY` | Leave blank unless you switch `AI_PROVIDER` to `groq` |
   | procureai-backend | `SERPAPI_KEY` | Optional — leave blank to skip live Google Shopping prices |

   `JWT_SECRET` is auto-generated by Render (`generateValue: true`) — you
   don't need to set it.

5. Click **Apply**. Render provisions both services and starts the first
   build/deploy.

## 3. MongoDB Atlas network access

Render's outbound IPs are dynamic on the free plan. In Atlas, go to
**Network Access** and add `0.0.0.0/0` (allow from anywhere) — this is the
standard approach for PaaS platforms without static egress IPs. Restricting
by IP is only possible on paid Render plans with a static outbound IP add-on.

## 4. Verify the deployed URLs match render.yaml's assumptions

`render.yaml` hardcodes:

- Backend: `CORS_ORIGINS=https://procureai-frontend.onrender.com`
- Frontend: `REACT_APP_BACKEND_URL=https://procureai-backend.onrender.com`

Render assigns `<service-name>.onrender.com` **unless that name is already
taken globally**, in which case it appends a random suffix (e.g.
`procureai-backend-x7k2.onrender.com`). After the first deploy:

1. Open each service in the Render dashboard and check its actual URL at the
   top of the page.
2. If either URL differs from the hardcoded assumption above, update the
   corresponding env var (`CORS_ORIGINS` on the backend, or
   `REACT_APP_BACKEND_URL` on the frontend) in **Environment** settings to
   the real URL, then trigger **Manual Deploy → Deploy latest commit** on the
   affected service so the change takes effect (the frontend var is baked in
   at build time, so it needs a rebuild, not just a restart).

## 5. First boot seeds the database

On first successful connection, the backend seeds categories, suppliers, the
demo user (`demo@procureai.com` / `Demo@123`), sample search history, and demo
Supplier Hub data. If `SERPAPI_KEY` is set, this first boot also makes ~14
live SerpAPI calls (one per seeded sample search), which can add 30–90s to
the first startup — this is expected and only happens once.

## 6. Smoke test

- `GET https://<backend-url>/health` → `{"status":"ok"}`
- Visit the frontend URL, click **Try Demo Workspace** (or log in with the
  demo credentials above), and confirm the dashboard loads data.

## Local development

- `backend/.env.example` and `frontend/.env.example` list every variable the
  app reads. Copy each to `.env` in the same folder and fill in real values —
  both `.env` files are gitignored.
- Backend: `cd backend && pip install -r requirements.txt && uvicorn server:app --reload --port 8001`
- Frontend: `cd frontend && yarn install && yarn start`
